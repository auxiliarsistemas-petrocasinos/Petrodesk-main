# Refactor code
1. Identify concrete duplication, coupling, size, unsafe types, unclear ownership, or test friction.
2. Establish behavior with existing or characterization tests.
3. Propose the smallest cleaner design, alternatives, migration risk, and expected benefit.
4. Refactor in reviewable steps; preserve contracts and avoid speculative abstractions.
5. Prefer feature boundaries, composition, typed utilities, and cohesive functions.
6. Compare complexity/testability before and after; run full proportional verification.
